# Vanish

> 자율 주행 기반의 자동 주차 및 복귀 시스템
> 

## 기획 의도

<aside>

자율주행을 활용하여 승하차의 불편함을 최소화하고, 차량이 스스로 주변 주차장을 탐색하여 주차한 후, 사용자의 호출 시 자동으로 현재 위치로 복귀하는 시스템을 구현함으로써 기존 차량 서비스의 부가 가치를 극대화한다.

</aside>

## 배경

최근 모빌리티 서비스 발전과 함께 자율주행 기술과 스마트 주차 시스템에 대한 관심이 증대되고 있다. 도시 내 차량 증가와 주차 공간 부족 문제는 갈 수록 심해지고 있으며, 기존 네이티브 앱 기반 주차 및 호출 서비스는 하차 후 경험 개선에 한계가 있음이 지적되고 있다. 테슬라의 Smart Summon 등이 서비스 되고 있으나, 제한된 환경과 기능적 제약으로 인해 보다 통합적이고 혁신적인 서비스 구현의 필요성이 대두되고 있다.

## 목적

본 프로젝트의 목적은 자율주행 기반의 자동 주차 및 복귀 시스템을 구현하여 차량 사용자의 편의성을 극대화하는 데 있다. 구체적으로, 사용자가 하차한 후 차량이 스스로 최적의 주차 공간을 탐색·주차하고, 필요 시 원격 호출을 통해 자동으로 현재 위치로 복귀하는 기능을 제공함으로써 기존 주차 시스템의 한계를 극복하고자 한다. 또한, 주차장 도착 시 자동 결제 및 데이터 연동 기능을 통해 통합적인 모빌리티 서비스를 실현하며, 실제 경로 데이터와 시뮬레이션 환경을 연계하여 시스템의 현실성과 신뢰성을 확보하는 것을 목표로 한다.

## 서비스 기능

- **사용자 앱을 통한 원격 호출 시스템**
- **하차 시 자동 주차 및 배회 대기 시스템**
    - 차량이 하차 후 자동으로 주차장으로 이동하고, 주차 공간이 없는 경우 차량 및 사용자 상태에 따라 주변 배회.
- **주차장 자동 결제 시스템**
    - 주차장 도착 시 자동 결제 진행 및 관련 데이터 연동.
- **모바일, 인포테인먼트**
    - 프로그레시브 웹 앱 형태로 구현하여 결제, 호출, 개인 등록 등 주요 기능 지원.
    - 차량 인포테인먼트를 활용하여 자동 주차 및 경로 관련 서비스 지원
- **데이터 활용 및 시뮬레이션**
    - 실제 경로 및 환경 요소(예: 한강 주변) 데이터를 활용할 가능성 검토
    - 모라이(morai)를 통한 가상 환경 내 경로, 도로 데이터 추출 및 지오스페셜 형식으로 변환하여 저장
- **주차장 인식 및 구현 방식**
    - 주차장 내부의 실제 주차 행위는 구현하지 않고, 주차장 도착 과정 및 결제 과정을 구현.

**추가 필요**: 각 기능별 세부 구현 방안 및 UI/UX 구체화

## 기존 서비스(유사 서비스)와의 차별점

- **기존 서비스**
    
    **테슬라**
    
    - 차량 소유자가 단기적으로 차량을 호출할 수 있도록 돕는 기능(Smart Summon)을 제공하여, 주차장에서 차량을 찾거나 짧은 거리를 이동할 때 도움을 줌.
    - 주로 개인 차량 이용에 집중되어 있으며, 호출 기능이 비교적 제한된 환경(예: 주차장 내)에서 작동.
- 차별점
    - **원격 호출 및 자동 복귀:** 사용자가 앱으로 차량을 호출하면, 차량이 자동으로 현재 위치까지 복귀.
    - **자동 주차 및 배회:** 하차 후 차량이 스스로 최적의 주차 공간을 찾아 주차하고, 필요시 대기 및 경로 재설정.
    - **자동 결제 시스템:** 주차 결제가 자동으로 이루어져 추가적인 번거로움을 줄임.

## 프로젝트 타당성

- 차량 사용자 경험의 혁신 가능성 및 시장의 요구 반영
- 실제 주행 및 주차 관련 데이터 연동을 통한 시스템의 현실성 검토 필요

**추가 필요**: 타당성 분석(시장 조사, 기술적 검증, 경제성 분석 등) 상세 자료

## 고려 사항

- **데이터 활용**
    - 리얼 월드 데이터(예: 한강 경로, 도로 환경)와 시뮬레이션 환경 간의 차이점 고려
    - 모라이(morai)를 통한 가상 경로 사용
- **주차장 인식**
    - 주차장을 가상 환경 내에 구현이 힘들 경우 영역을 설정하여 주차장으로 구현하는 방안 고려
- **배회 기능**
    - 인근 주차장 공간 부족 시 배회에 따른 연료 소모, 경로 설정 등 다양한 변수 고려 필요
    - 백엔드에서 차량 및 사용자 상태에 따라 경로 재설정 기능 필수
- **자동 결제 시스템**
    - 결제 관련 보안 및 신뢰성 확보 방안 마련 필요

**추가 필요:** 각 고려 사항별 상세 검토 및 위험 요소 분석

## 구현 방식

- **자동 주차 및 배회 대기 시스템**
    - 차량 하차 후 자동 주차장 이동 및 배회 대기 기능 구현
    - 백엔드에서 차량 상태 및 사용자 요청에 따른 경로 최적화 기능 도입
- **주차장 자동 결제 시스템**
    - 주차장 도착 시 자동 결제 및 데이터 연동 구현
- **데이터 활용 및 시뮬레이션**
    - 실제 데이터와 시뮬레이션 환경 간의 연계성 검토
    - 모라리(morai) 활용 여부 및 가상 환경 내 경로 데이터 추출 방식 검토
- **인포테인먼트 시스템**
    - 네이티브 앱 또는 프로그레시브 앱 개발을 통한 모바일 환경 구현

**추가 필요:** 구체적인 아키텍처 설계, 프로토타입 개발 계획, 테스트 시나리오 등

### 차량 호출 시나리오

### 목표

사용자가 원하는 위치에서 차량을 원격으로 호출하여 차량이 자동으로 사용자의 위치로 이동하도록 한다.

### 참여자

- **주 사용자**: 차량 소유자 (운전자)
- **시스템**: 원격 호출 시스템, 자율 주행 시스템, 서버 (현재 위치확인 및 경로 설정)

### 사전 조건

- 차량이 주차되어 있고, 원격 호출 기능이 활성화되어 있어야 한다.
- 사용자의 스마트폰에 Vanish 앱이 설치되어 있고, 로그인 상태여야 한다.
- 차량과 Vanish 앱이 네트워크로 연결되어 있어야 한다.

### 기본 흐름

1. 사용자가 Vanish 앱을 실행하여 "차량 호출" 기능을 선택한다.
2. 현재 위치가 지도 상에 자동으로 표시되며, 사용자는 차량 호출을 요청한다.
3. 시스템은 차량의 현재 위치와 사용자의 위치를 비교하여 최적 경로를 설정한다.
4. 차량은 자율 주행을 통해 사용자의 위치로 이동한다.
5. 차량이 도착하면 앱에 "차량 도착" 알림이 전송된다.
6. 사용자는 차량에 탑승하여 주행을 시작한다.

### 예외 흐름

- **경로 장애물 발생**: 이동 중 장애물이 발생할 경우, 차량은 경로를 재설정하고 사용자는 앱을 통해 경로 재설정 사실을 안내받는다.
- **네트워크 오류**: 호출 중 네트워크 문제가 발생하면, 사용자는 "호출 실패, 다시 시도해 주세요"라는 메시지를 받는다.
- **주차장 출입 제한**: 차량이 주차장에서 출입이 불가능한 경우, 사용자는 "출입 불가, 수동 조작 필요"라는 메시지를 받는다.

### 결과

- 차량은 사용자의 호출에 따라 정확하게 현재 위치로 도착한다.
- 사용자는 편리하게 차량을 호출하고 이동할 수 있다.

# Docker 레이어의 기본 개념

## 불변성
- Dockerfile의 각 명령어 (FROM, RUN, COPY 등)는 새로운 레이어를 생성하며, 각 레이어는 변경 불가능합니다.

## 캐시 활용
- 도커는 이전 빌드의 레이어를 캐시하여, 동일한 명령어가 반복될 때 재빌드를 방지합니다.
- 이를 위해 자주 변경되지 않는 명령어는 상단에 배치하는 것이 좋습니다.

# 최적화 방법

## 명령어 결합
- 여러 RUN 명령어를 하나의 RUN 명령어로 합치면 중간 레이어를 줄일 수 있습니다.

```Dockerfile
RUN apt-get update && apt-get install -y package1 package2 && \
    rm -rf /var/lib/apt/lists/*
```
## 불필요한 파일 제거
- 빌드 과정에서 생성되는 임시 파일이나 캐시 파일은 즉시 삭제하여 최종 이미지 크기를 줄입니다.

## 멀티 스테이지 빌드
- 빌드 단계와 최종 실행 환경을 분리하여, 빌드에 필요한 파일만 최종 이미지에 포함시키는 방법입니다.

```Dockerfile
FROM builder AS build
RUN make build

FROM alpine
COPY --from=build /app /app
CMD ["/app/start"]
```

## .dockerignore 활용
- 빌드 컨텍스트에 포함될 불필요한 파일을 제외시켜, 이미지 빌드 과정의 효율을 높입니다.
